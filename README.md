# FluxLab

**An independent, local-first fluid-dynamics workbench in plain HTML, CSS, JavaScript, and WGSL.**

FluxLab combines a Fluent-inspired ribbon / outline / task-page workflow with editable 2D geometry, a real D2Q9 lattice Boltzmann solver, and scientific field visualization. It has no runtime package dependencies, remote fonts, CDN scripts, telemetry, or cloud solver. All numerical fields are calculated from the configured initial and boundary conditions, not generated from decorative animation formulas.

**Release scope:** a working 2D, laminar, isothermal, low-Mach CFD workbench. This is not a complete Ansys Fluent clone, a Fluent file-format implementation, or a validated engineering-design product. The WebGPU implementation is included, but device execution could not be verified in the build environment. Read [validation status](docs/VALIDATION.md) before interpreting results.

**[Launch FluxLab](https://wieslawsoltes.github.io/FluxLab/)** · **[Standalone app](https://wieslawsoltes.github.io/FluxLab/fluxlab-standalone.html)**

See [deployment documentation](docs/DEPLOYMENT.md) for the GitHub Pages pipeline. Browser screenshots are generated by `npm run test:browser`.

## Run

Requires Node.js 20 or newer for the included development server. There is nothing to install with npm.

```sh
cd fluxlab
npm start
```

Open `http://localhost:4174` in a WebGPU-capable browser. WebGPU needs a secure context, normally HTTPS or a trustworthy localhost origin; availability also depends on the browser, GPU, drivers, and administrator policy. [WebGPU API documentation](https://developer.mozilla.org/en-US/docs/Web/API/WebGPU_API).

The compute-environment card identifies the actual selected backend:

- **WebGPU:** GPU compute and GPU-resident scalar rendering; CPU overlays consume periodic snapshots.
- **CPU · Worker:** the reference solver runs in a dedicated Web Worker; Canvas 2D renders the field.
- **CPU · Cooperative:** last-resort reference solver that yields between individual time steps when workers are unavailable.

The server binds only to `127.0.0.1` by default. Set `PORT` to choose another port; set `HOST` explicitly for LAN access. Serving through an ordinary LAN HTTP origin does not make WebGPU available.

Alternatively, open `fluxlab-standalone.html`. It contains the CSS, application, worker source, shaders, and embedded setup / numerical-method documentation in one file. Browser security policy may prevent WebGPU or workers on local files; the cooperative solver is available as a fallback. The localhost route is preferable for GPU use and local autosave.

Useful query switches: `?paused` starts paused; `?fresh` ignores the saved case; `?cpu` forces the CPU backend. They can be combined, for example `?fresh&paused&cpu`.

## Included functionality

| Area | Implemented behavior |
|---|---|
| Workspace | Home, Geometry, Mesh, Setup, Solution, Results, and View ribbons; searchable outline; property task pages; viewport tools; console; monitor, probe, and summary panels; light/dark theme; responsive layout |
| Geometry | Select and drag bodies; create circles / ellipses, rectangles, symmetric NACA-profile airfoils, and closed polygons; edit position, dimensions, rotation, and thickness where applicable; duplicate and delete; transactional undo/redo |
| Import | Versioned FluxLab case JSON; body JSON; SVG circles, ellipses, rectangles, polygons, and simple closed paths |
| Mesh | Uniform Cartesian lattice, cell-mask generation, grid inspection, stability-parameter checks, resolution changes, mesh overlay |
| Physics | D2Q9 TRT or BGK collision; pull streaming; link bounce-back; moving-lid cavity; velocity inlet and density/pressure outlet; uniform or parabolic inlet; lateral periodic boundaries |
| Solution | Initialize, calculate, pause, single-step / batch, target iteration, measured temporal-change monitors, numerical-health stop, optional temporal-convergence stop |
| Results | Velocity magnitude, X/Y velocity, gauge pressure, and Z vorticity; four palettes; auto/manual color ranges; contour bands; vectors; RK2 streamlines; passive particles; measurement probes |
| Files | Local case autosave; JSON save/load; field CSV; legacy structured VTK; monitor CSV; probe CSV; summary JSON; viewport PNG |
| Examples | Airfoil water tunnel, cylinder wake, lid-driven cavity, laminar channel, converging passage, and cylinder array |

Geometry and physical-model changes **reinitialize** the distribution functions. Case save/load stores configuration, not a restart checkpoint. Display changes preserve the simulation state. Undo/redo applies to case definitions, not numerical history.

### First session

The default example is a NACA 0012-like symmetric airfoil in a low-speed water tunnel. Let it calculate, then pause. Select the airfoil in the outline, change **Rotation (counterclockwise)**, and apply: the flow restarts around the new geometry. Use the field selector to switch to gauge pressure or vorticity. Choose the probe tool and click a fluid cell, then export CSV or VTK from Results.

The sample airfoil uses a mathematical symmetric thickness profile with a closed trailing edge, not imported CAD. The smooth visible outline is rasterized to solid lattice nodes; the numerical wall is stair-stepped. Refinement matters.

## Numerical contract

All persisted lengths, density, dynamic viscosity, reference velocity, and exported physical fields use SI units. The UI may display millimetres for geometry. The solver explicitly maps these quantities into lattice units. It rejects unsupported relaxation-time combinations instead of silently increasing viscosity to stabilize a pretty picture.

The mesh supports 48–1024 columns, 24–1024 rows, and at most 1,048,576 nodes, subject to numerical and device-memory constraints. This is an allocation / input limit, not a performance claim. Curved-body accuracy is limited by uniform-grid resolution and the solid-node representation.

The residual display measures normalized changes in velocity and density between snapshots per lattice step. It is **not** a Fluent finite-volume equation-residual history. Low temporal changes alone do not prove physical accuracy, mesh convergence, or a steady solution. See [NUMERICS.md](docs/NUMERICS.md) for equations, boundary reconstruction, SI mapping, error sources, and interpretation.

## Architecture

```text
src/model.js       Versioned cases, SI/lattice mapping, geometry, rasterizer, history
src/cpu.js         Reference D2Q9 pull-stream / TRT-BGK solver
src/worker.js      Transferable-snapshot worker protocol
src/gpu.js         WebGPU buffers, pipelines, scheduling, readback, fallback backends
src/solver.wgsl    128-thread compute kernel, one lattice node per invocation
src/render.wgsl    Fullscreen scientific scalar renderer
src/diagnostics.js Field statistics, probes, temporal monitors, CSV / VTK export
src/viewport.js    Camera, rendering, scientific overlays, RK2 trajectories
src/ui.js          Ribbon, tree, task-page and bottom-panel rendering
src/app.js         Application state, edit transactions, async lifecycle, file actions
src/icons.js       Original inline SVG interface icons
```

The GPU path stores two nine-population structure-of-arrays buffers, a solid-node mask, and a four-component macroscopic field. Each dispatch reads only the source distribution buffer and writes the other buffer; bindings alternate between steps. The scalar renderer reads that same GPU field buffer. A staging buffer provides asynchronous readback for diagnostics and overlays. Generation guards prevent stale case initialization / readback from replacing newer state; device loss restarts the case on the CPU rather than pretending to continue the lost solution.

`tools/build-standalone.py` is a project-scoped, standard-library-only linker, not a general JavaScript bundler. It accepts this repository's named-import / declaration-export module graph and fails on unsupported syntax.

## Verification

```sh
npm test                     # 13 numerical, model, serialization and worker tests
npm run build:standalone      # Requires Python 3

# Optional browser-test tooling, not an application dependency:
python3 -m pip install playwright
python3 -m playwright install chromium
npm run test:browser
```

To use an existing Chromium binary, set `CHROMIUM_PATH`. The browser suite starts the server on port 4174; stop any existing server on that port first. `python3 tests/browser.py --memory` tests the standalone app without navigation in restricted environments. It does not change browser policies or replace numerical code with mocks.

The recorded build passed **13 core/worker tests and 19 browser checks** with no uncaught JavaScript errors. The analytical periodic shear-wave amplitude errors were **0.0706% (TRT)** and **0.1853% (BGK)** for the documented test. These are narrow verification results, not general accuracy guarantees. Browser tests here exercised the real cooperative CPU solver. GPU execution and CPU/GPU parity were **not executed** because no adapter was exposed. The served browser suite attempts parity when an adapter is available. Full details and evidence are in [VALIDATION.md](docs/VALIDATION.md) and `test-results/`.

## Known limits

There is no 3D solver or viewer, unstructured / adaptive mesh, pressure-based finite-volume solver, turbulence model, energy equation, compressible-shock solver, reacting flow, radiation, conjugate heat transfer, multiphase model, FSI, moving mesh, arbitrary prescribed outlet pressure, force integration, particle-to-fluid coupling, distributed solver, or population-state checkpoint. SVG import is deliberately limited: flatten transforms first; holes, compound/open paths, and active SVG are not imported. No Fluent `.cas`, `.dat`, or `.msh` compatibility is claimed.

Before engineering use, the implementation needs actual GPU qualification, systematic refinement studies, quantitative cavity and cylinder benchmarks, conservation budgets, boundary-accuracy studies, and validation against experimental or independently verified reference data. Do not use the current build as the sole basis for safety-critical design decisions.

## Deploy

The modular app is static. Publish `index.html`, `style.css`, `favicon.svg`, `src/`, `docs/`, and `README.md` through an HTTPS static host, or publish the single HTML file. No account keys, build service, server-side solver, or backend API are required. No public deployment has been created with this package.

The included `.github/workflows/ci.yml` runs numerical tests and creates downloadable site artifacts. It does not publish a site or make changes to an account.
